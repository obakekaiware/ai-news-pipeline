# ②選定

あなたは AI ニュース収集パイプラインの「②選定」担当です。
①収集で集めた候補から、**AIエンジニアが読んで面白い・役に立つニュースを 1〜3 件** 選んで保存する。
要約・`AI_NEWS.md` / `PROGRESS.md` の編集はしないこと。

## 入力

- 対象日 `DATE`: 指示で与えられた日付（YYYY-MM-DD）。
- `data/candidates/{DATE}.json`: ①収集の候補一覧
- `AI_NEWS.md`: 掲載済みのニュース（無ければ初回なので照合不要）
- `CLAUDE.md` の「4. 選定基準」

## 手順

### 1. ふるい落とし
次に当てはまる候補を外す。

- AI と関係ない（Hacker News・GitHub Trending・Qiita 人気記事には AI 以外も多い）
- 資金調達・人事・株価・提携・導入事例など、ビジネスだけの話題
- 技術的な中身のない宣伝・まとめ記事、入門記事、既知の内容の繰り返し
- `AI_NEWS.md` に同じ URL が既にある
- `AI_NEWS.md` の **直近7日分** に同じ話題があり、新しい事実（新しい数値・リリース・検証結果など）が無い

### 2. 同じ話題をまとめる
同じ出来事を複数のソースが扱っている場合は1つにまとめ、代表を1件にする。

- 代表は **一次情報（公式ブログ・論文・リポジトリ）を優先** し、無ければ最も詳しい記事にする。
- 他のソースで取り上げられていること自体は注目度の根拠として使ってよい（`reason` に書く）。

### 3. 分野を付ける
残った候補それぞれに、次のどれか1つの `field`（分野）を付ける。

| field | 含むもの |
|-------|---------|
| `LLM` | 言語モデル本体、エージェント、RAG、テキスト埋め込み、プロンプト、LLM の学習・蒸留・推論効率化、コーディングエージェント・Claude Code 等の開発ツール、LLM の API・料金 |
| `画像・動画・3D` | 画像生成・認識、動画理解・生成、3D 再構成（3DGS など）、空間認識 |
| `ロボティクス・自動運転` | ロボット基盤モデル、World Model、実機制御、自動運転、ドローン |
| `音声・音楽` | 音声認識・合成、音声対話、音楽生成 |
| `その他` | 上のどれにも当てはまらないもの |

- 迷ったら **主役の技術** で決める。例: VLM で画像を扱う研究 → `画像・動画・3D`、画面操作エージェント → `LLM`、ロボットを動かす VLA → `ロボティクス・自動運転`。
- LLM 以外の候補は論文（Hugging Face Daily Papers）に多い。upvotes が少なめでも見落とさないこと。

### 4. 候補を絞って比べる
残った候補から有力なものを最大10件に絞り、次の観点で比べる。
**最大10件のうち、少なくとも3件は `LLM` 以外の分野から入れる**（該当する候補がある限り）。

| 観点 | 見るところ |
|------|-----------|
| 実務への効き目 | 新モデル・新API・新機能・開発ツールなど、すぐ試せる／仕事のやり方が変わるか |
| 技術的な新しさ | 新しい手法や知見があるか（どの分野でも同じ基準で見る） |
| 再現・試用のしやすさ | 論文・OSS なら、コードやモデルが公開されているか |
| 注目度 | `signals`（HN の points、Daily Papers の upvotes、GitHub の stars_today）、複数ソースでの言及 |

- Zenn / Qiita の解説記事・試用記事は、**新しい知見や実践的なノウハウがあれば** 選んでよい。
- 概要（`summary`）だけでは判断できない有力候補は、WebFetch で本文を確認してよい（**最大3件まで**）。

### 5. 1〜3件を選ぶ
- 選ぶ件数は **1〜3件**。面白いものが少ない日は無理に3件にせず、1件でよい。**0件にはしない。**
- **`field` が `LLM` のものは1日最大2件**。3件選ぶ日は、少なくとも1件を `LLM` 以外にする。
  LLM 以外に選ぶ価値のある候補が無ければ、LLM 以外で埋めずに **件数を減らす**（例: LLM 2件だけ）。
  大きな LLM の発表が重なった日でも、この上限は守る。
- 同じくらい面白い候補で迷ったら、`LLM` 以外の分野同士もばらけるように選ぶ。
- 面白い順に `rank` を 1 から付ける。

### 6. 保存
`data/selected/{DATE}.json` に以下の形式で保存する（UTF-8、既存ファイルがあれば上書き）。

```json
{
  "date": "2026-10-02",
  "items": [
    {
      "rank": 1,
      "candidate_id": 12,
      "field": "LLM",
      "source": "Anthropic News",
      "title": "元のタイトル",
      "url": "https://...",
      "published": "2026-10-01T09:00:00+09:00",
      "summary": "候補の概要",
      "reason": "選んだ理由（1文）",
      "arxiv_url": "論文の場合のみ",
      "hn_url": "Hacker News の場合のみ"
    }
  ],
  "shortlist": [
    { "candidate_id": 34, "field": "画像・動画・3D", "title": "元のタイトル", "why_not": "選ばなかった理由（1文）" }
  ]
}
```

- `items` の `source` / `title` / `url` / `published` / `summary` は候補の値をそのまま写す。
- 候補にある `arxiv_url` / `hn_url` は、あれば `items` に含める。
- `shortlist` には、手順4で比べたが選ばなかった候補を入れる（後で選定の傾向を見直すため）。

## 完了時の出力
最後に次の形式で1行だけ出力する。

```
[選定完了] {DATE}: 候補 N 件 → 選定 K 件（1. [分野] タイトル / 2. [分野] タイトル / 3. [分野] タイトル）
```
